# 디자인 기획 설명 작성 양식

학생 이름: 강민경 
브랜드명: DAMORI
웹사이트 목적: 종이와 디지털 사이에서 사용자가 자신에게 맞는 기록 방식을 찾고, 한 줄 기록이나 템플릿으로 부담 없이 시작한 뒤 기존 기록으로 다시 돌아올 수 있도록 돕는 것
주요 사용자: 기록을 시작하고 싶지만 도구 선택이나 꾸준함에 부담을 느끼는 사용자, 종이 다이어리의 감각과 디지털 기록의 편리함을 함께 원하는 사용자
핵심 디자인 키워드 3개: Calm Editorial, Tactile Diary, Functional Utility

## 작성 방법

- 아래 1~13번을 모두 작성합니다.
- `초안 기획 의도`에는 무엇을 바꿨는지가 아니라 누구를 위해 왜 그렇게 정했는지 씁니다.
- 최종에서 변경한 항목은 문제점·추가 리서치·최종 변경·기대 효과를 모두 작성합니다.
- 변경하지 않은 항목은 `최종 결정`에 유지라고 표시하고, 유지 이유를 작성합니다.
- 초안과 최종안은 최소 3개 항목만 달라도 됩니다.

## 전체 프로세스

### 1단계. 기본 스타일가이드 파악

- 원본 스타일가이드의 목적과 특징: 색상·타이포그래피·간격·효과의 기초 규칙과 버튼·배지·진행·선택·카드 컴포넌트를 13개 이미지로 나누어 일관된 화면 제작 기준을 제시한다.
- 유지하고 싶은 원칙: Foundation에서 Component로 확장되는 순서, 상태별 차이, 반복 가능한 간격과 크기, 한 장에 하나의 주제를 설명하는 방식
- 내 브랜드와 맞지 않는 부분: 퀴즈·정답·오답·타이머 중심의 상태와 높은 정보 밀도는 기록의 자율성과 차분한 브랜드 인상을 전달하기 어렵다.

### 2단계. 내가 좋아하는 디자인 리서치

| 사례·출처 | 좋아하는 구체적 요소 | 좋아하는 이유 | 내 작업에 적용할 원리 |
|---|---|---|---|
| A24 UXUI, Behance | 큰 Serif 제목과 절제된 편집 레이아웃 | 기록물의 감성과 정보 위계를 함께 표현할 수 있기 때문 | Display에는 Serif, 기능 정보에는 Sans-serif를 분리 적용 |
| Stay Product Platform Redesign, Behance | 단계와 선택 상태가 분명한 기능 화면 | 사용자가 현재 위치와 다음 행동을 예측하기 쉽기 때문 | 방식 찾기 Stepper와 Option 상태에 적용 |
| KakaoBank Careers, Behance | 넓은 여백과 명확한 콘텐츠 위계 | 많은 설명을 한꺼번에 강조하지 않고 순서대로 읽게 하기 때문 | Section 간격과 대표·보조 정보의 크기 차이에 적용 |
| 숲소리, GDWEB | 자연 소재 색상, Cream 배경과 Olive 계열 포인트 | 종이와 생활 기록의 차분하고 촉각적인 분위기에 적합하기 때문 | Foundation Color와 Editorial 이미지 방향에 적용 |

### 3단계. 초안 스타일가이드 방향

- 초안 콘셉트: 종이와 디지털을 동등하게 연결하는 Calm Editorial Utility
- 대상 사용자가 받아야 할 인상: 조용하고 따뜻하지만 기능은 명확하며, 기록을 완벽하게 해야 한다는 압박이 없는 인상
- 색·서체·형태·밀도 기본 방향: Cream·Olive·Brown의 저채도 색상, Serif 제목과 Sans-serif UI 조합, 기능 카드의 절제된 Radius, 넓은 여백과 제한된 대형 타이포그래피

### 4단계. 웹디자인 초안

- 브랜딩 와이어프레임의 핵심 구조: Hero, 3단계 기록 방식 찾기, 한 줄 기록, Analog/Digital 비교, 원본과 사본, 다시 이어가기, 기능 상태 안내
- 스타일가이드를 웹 화면에 적용한 방식: Olive Primary Button, Cream Canvas, Serif Display, 12열 Grid와 8~16px Radius를 공통 토큰으로 적용했다.
- 초안에서 우선 확인한 내용: 브랜드 색상 분위기, 기록 방식 추천 흐름, 작은 기록 입력, 상태를 과장하지 않는 기능 안내

### 5단계. 마음에 들지 않는 디자인 확인

- 가장 개선이 필요한 항목 3개 이상: 제목의 어색한 한 글자 줄바꿈, 일반 웹사이트처럼 보이는 상단바, 메모장 중심 Hero, 반복 카드로 인한 단조로움, 로그인과 기존 작업 복귀 진입 부재, Analog/Digital의 시각적 차이 부족
- 각 항목이 마음에 들지 않는 구체적인 이유: “돼/요.”처럼 의미가 끊겼고 상단바가 브랜드 장면과 분리되어 보였으며, 메모장은 쿠션 다이어리 중심 브랜드를 충분히 설명하지 못했다. 비교 영역은 설명문만 나뉘어 두 방식의 차이가 즉시 보이지 않았고 기존 사용자가 작업으로 돌아갈 경로도 없었다.
- 브랜드·사용자·가독성·일관성에 미치는 영향: 브랜드의 다이어리 정체성이 약해지고 사용자가 핵심 서비스를 빠르게 이해하기 어려우며, 문장 가독성과 섹션별 시각 위계가 낮아진다.

### 6단계. 개선용 디자인 리서치

| 개선할 문제 | 새 사례·출처 | 사례에서 발견한 해결 원리 | 적용 계획 |
|---|---|---|---|
| 추천이 정답처럼 보일 수 있음 | Stay Product Platform Redesign, Behance | 시스템 제안과 사용자 선택 상태를 시각적으로 구분 | Recommended와 Selected의 Label·Icon을 다르게 적용 |
| 진행 표시가 성취율처럼 보임 | KakaoBank Careers, Behance | 완료율보다 현재 위치와 다음 행동을 명확히 안내 | 목적·시작 크기·매체 조건의 Pressure-free Stepper로 수정 |
| 시간이 기록 압박으로 작용함 | 원본 능력단위평가 Timer | 경고 Countdown 대신 예상 소요 시간과 현재 상태를 분리 | 약 5·15·30분 Duration과 READY·IN PROGRESS·PAUSED로 수정 |
| 기능 상태가 모호함 | Stay Product Platform Redesign, Behance | 상태명, 영향, 가능한 행동을 함께 제공 | PROTOTYPE·LOCAL·PENDING·HOLD 등의 Badge 체계 적용 |
| 작은 화면의 문장 줄바꿈 | v2 Mobile Line Break Test | 화면 폭별 실제 문장 줄바꿈을 사전에 비교 | 360·320·280px에서 제목과 본문을 검수 |

### 7단계. 최종 스타일가이드 방향

- 최종에서 유지한 핵심 원칙: Cream·Olive 중심 색상, Serif와 Sans-serif 조합, 기록 자율성, 작은 시작, 기능 상태의 정직한 안내
- 최종에서 변경한 핵심 원칙: 추천과 선택을 구분하고, 시간은 마감이 아닌 예상 부담으로 표시하며, 현재 위치 중심의 비압박형 Progress와 기능 상태 Badge를 추가했다.
- 초안보다 나아진 점: 브랜드 감성을 유지하면서 Button, Badge, Stepper, Option, Duration, Card의 사용 규칙과 접근성 상태가 구체적으로 정리되었다.

### 8단계. 최종 웹디자인

- 최종 스타일가이드를 반영한 영역: Hero, 3단계 방식 찾기, 추천 결과, 한 줄 기록, Analog/Digital 비교, 원본과 사본, 다시 이어가기, 제공 범위
- 와이어프레임과 최종 화면의 연결: Stepper와 Option을 방식 찾기에, Button과 Duration을 작은 기록에, Badge와 Card를 제공 범위와 복귀 영역에 적용했다.
- 대상 사용자와 브랜드에 적합하다고 판단한 이유: 기록 방식에는 정답이 없다는 원칙을 유지하면서 선택, 추천, 현재 위치, 임시 저장 범위를 명확하게 알려주기 때문이다.

- 초안 기획 의도: 기록을 부담스러운 관리가 아니라 차분한 생활 방식으로 받아들이게 하기 위해 어두운 Olive 배경과 종이 오브젝트를 사용했다.
- 초안에서 수정한 내용: DAMORI 명칭, 브랜드 문장, Calm Editorial Utility 키워드와 Analog/Digital 상징을 추가했다.
- 초안 검토 의견: 색상은 적합했지만 메모지 인상이 강해 쿠션 다이어리 중심성이 더 필요했다.
- 추가 리서치와 출처: PIT A PET의 제품 단독 Object Focus, LUSH App Redesign의 Device Presentation

- 최종 변경 또는 유지 이유: 어두운 Ink 배경, 큰 DAMORI Serif 제목, 종이 질감과 A/D 상징으로 13장 중 가장 강한 브랜드 진입 화면을 만들었다.
- 웹디자인과의 연결: v2 Hero의 종이 기록과 Digital 기록 화면, Cream·Olive 색상 대비와 연결된다.

## 2. Getting Started

- 원본에서 파악한 역할·특징: 디자인 시스템의 사용 목적과 시작 방법을 안내한다.
- 초안 기획 의도: 사용자가 기록 방식의 선택 구조와 브랜드 원칙을 먼저 이해하도록 한다.
- 초안에서 수정한 내용: Brand Promise, 기록 방식 탐색부터 복귀까지의 Information Architecture를 구성했다.
- 초안 검토 의견: 첫 화면에서 가능한 선택을 너무 많이 보여주면 부담이 생길 수 있어 행동 순서의 위계가 필요했다.
- 추가 리서치와 출처: 아임웹과 미리캔버스의 템플릿 선택 후 시작 구조
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Foundation, Component, Pattern, State, Page의 제작 순서와 방식 이해와 비교, 가장 작은 시작, 부담 없는 복귀라는 세 사용자 원칙을 함께 제시했다.
- 웹디자인과의 연결: v2 HTML의 방식 찾기, 작은 기록, 방식 비교, 다시 이어가기 순서로 연결된다.

## 3. Foundations — Colors

- 원본에서 파악한 역할·특징: 원시색과 상태 의미색을 정의해 화면 전체의 일관성과 상태 인지를 돕는다.
- 초안 기획 의도: 종이와 자연 소재의 차분함을 유지하면서 행동과 상태는 분명하게 구분한다.
- 원시색과 의미색 수정 내용: Ink #20231D, Olive #4F603F, Sage #B8C5A9, Cream #F7F2E9, Paper #FFFDF8을 기본으로 하고 완료·진행·주의·포커스 색을 분리했다.
- 색상 선택의 브랜드·사용자 근거: 저채도 자연색은 쿠션 다이어리와 종이의 촉각적 인상을 전달하고, 제한된 의미색은 기능 상태를 빠르게 구분하게 한다.
- 초안 검토 의견: 전체 색상 만족도가 높아 브랜드색은 변경하지 않고 상태색의 사용 범위만 명확히 할 필요가 있었다.
- 추가 리서치와 출처: 숲소리의 자연 소재 색상과 여백, PIT A PET의 제한된 색면 대비
- 최종 결정: 유지
- 최종 변경 또는 유지 이유: 기존 Cream·Olive 조합이 브랜드 인상과 사용자 요구에 적합해 색상 자체는 유지하고 용도만 정교화했다.
- 웹디자인과의 연결: Canvas, Header, Button, Diary, Template Card와 기능 상태에 같은 Token을 사용한다.

## 4. Foundations — Typography

- 원본에서 파악한 역할·특징: 제목·본문·레이블의 서체, 크기, 굵기와 행간 위계를 정의한다.
- 초안 기획 의도: Serif의 기록물 같은 분위기와 Sans-serif의 기능적 명료함을 함께 사용한다.
- 서체·크기·굵기·행간 수정 내용: Display 48/56, Section Title 32/44, Body 16/28을 기준으로 하고 대형 제목은 제한된 구간에서만 사용한다.
- 가독성과 브랜드 분위기 근거: 제목은 편집적이고 따뜻하게, 입력·버튼·상태 정보는 빠르게 읽히게 분리했다.
- 초안 검토 의견: “돼/요.”처럼 조사나 어미 한 글자가 다음 줄에 남는 문제가 있어 의미 단위 줄바꿈 검수가 필요했다.
- 추가 리서치와 출처: 뉴소스매거진의 대형 타이포그래피 대비, Saem.의 여백과 제목 배치
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: 서체 조합은 유지하고 word-break: keep-all, 의미 묶음 Span, Mobile 크기 상한과 검수 문장을 추가했다.
- 웹디자인과의 연결: Hero의 “기록은 남고, / 방식은 달라져도 돼요.”를 의미 단위로 고정하고 반응형에서도 한 글자 고립을 방지한다.

## 5. Foundations — Spacing & Sizing

- 원본에서 파악한 역할·특징: 반복 가능한 간격과 크기로 정렬, 밀도, 조작 영역의 일관성을 만든다.
- 초안 기획 의도: 기록을 천천히 읽는 브랜드 섹션과 빠르게 조작하는 기능 영역의 밀도를 구분한다.
- 간격 체계와 컨트롤 크기 수정 내용: 4·8·12·16·24·32·48·64·96 간격 체계, Web 12열 Grid, Button 최소 높이 48px을 적용했다.
- 화면 밀도와 조작 영역 근거: 기능 카드는 20~24px 내부 여백으로 묶고 편집 섹션은 96~144px 여백을 주어 읽는 호흡을 만든다.
- 초안 검토 의견: 동일한 카드 간격 반복으로 화면이 단조로워 섹션별 밀도 변화가 필요했다.
- 추가 리서치와 출처: 숲소리의 생활 장면과 카드 목록 교차, Saem.의 넓은 편집 여백
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: 기본 간격 체계는 유지하되 대표 장면, 보조 카드, Text Link 사이의 크기 대비를 확대했다.
- 웹디자인과의 연결: Hero, 비교, Gallery, Maker, Login 구간이 서로 다른 밀도를 가지면서 같은 Grid에 정렬된다.

## 6. Foundations — Radius & Effects

- 원본에서 파악한 역할·특징: 컨트롤과 카드의 모서리, 경계선, 그림자로 요소의 성격과 위계를 구분한다.
- 초안 기획 의도: 기능 화면은 절제되고 명확하게, Diary와 Device는 실제 물체처럼 촉각적으로 표현한다.
- 모서리·선·그림자 수정 내용: Control 8~12px, Functional Card 12~16px, Editorial Image 16px 또는 Organic Crop, 중앙 메뉴 Capsule 999px을 사용한다.
- 형태가 주는 인상과 위계 근거: 작은 Radius는 조작 가능성을 명확히 하고 큰 Radius와 Shadow는 부유하는 물체와 브랜드 장면을 강조한다.
- 초안 검토 의견: 모든 영역이 비슷하게 둥글면 위계가 약해지고 앱 카드처럼 단조로워질 수 있었다.
- 추가 리서치와 출처: 아린엠에이치씨의 중앙 메뉴 Capsule, 숲소리의 둥근 이미지 Crop
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Border를 Shadow보다 우선하고 그림자는 Diary, Device, Floating 상태에만 제한했다.
- 웹디자인과의 연결: 중앙 메뉴, Template Card, Login Card, Diary와 Device에 역할별 Radius와 Effect를 적용한다.

## 7. Components — Button

- 원본에서 파악한 역할·상태: 사용자의 주요 행동과 보조 행동을 기본·Hover·Focus·Disabled 상태로 구분한다.
- 초안 기획 의도: 사용자가 한 화면에서 가장 중요한 다음 행동 하나를 빠르게 찾게 한다.
- 크기·종류·상태 수정 내용: Primary Olive Fill, Secondary Outline, Tertiary Text의 세 위계와 최소 높이 48px을 적용했다.
- 주요 행동의 위계와 접근성 근거: Fill은 한 화면의 최우선 행동에만 사용하고 Keyboard Focus는 3px Blue Outline로 색상 대비를 확보한다.
- 초안 검토 의견: CTA가 여러 개 동일한 강도로 보이면 시작 선택에 부담이 생겼다.
- 추가 리서치와 출처: 아임웹과 미리캔버스의 선택 후 시작 CTA 위계
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Primary, Secondary, Tertiary, Destructive와 Default, Hover, Focus-visible, Pressed, Disabled, Loading 상태를 명시했다.
- 웹디자인 적용 위치: Hero CTA, 기록 방식 질문 이동, 한 줄 기록 상태 확인, 답 수정과 보류 행동

## 8. Components — Badge

- 원본에서 파악한 역할·상태: 짧은 분류와 상태를 작은 면적에서 빠르게 인식시키는 요소다.
- 초안 기획 의도: 기능이 실제로 제공되는 범위와 사용자에게 미치는 영향을 짧지만 오해 없이 알린다.
- 크기·톤·레이블 수정 내용: PROTOTYPE, LOCAL, PENDING, CONFLICT, HOLD, UNVERIFIED를 색상·아이콘·텍스트로 함께 구성했다.
- 짧은 상태 정보의 표현 근거: 상태명만 제시하지 않고 영향 설명과 가능한 행동을 같은 열에 연결한다.
- 초안 검토 의견: 완료되지 않은 기능도 시각적 완성도가 높으면 실제 기능으로 오해될 수 있었다.
- 추가 리서치와 출처: 미리캔버스의 템플릿 분류, 아임웹의 목록 탐색 구조
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: 브랜드 색과 상태색의 역할을 분리하고 각 상태에서 사용자가 할 수 있는 다음 행동을 함께 표시했다.
- 웹디자인 적용 위치: 빠른 기록의 LOCAL 상태와 제공 범위의 PROTOTYPE, LOCAL, PENDING, HOLD 카드

## 9. Components — Progress

- 원본에서 파악한 역할·상태: 전체 단계 중 현재 위치, 완료, 대기 상태를 순서와 연결선으로 전달한다.
- 초안 기획 의도: 기록 방식 추천을 성취율이나 평가가 아니라 현재 선택 위치로 이해하게 한다.
- 단계·톤·완료 표현 수정 내용: 목적, 시작 크기, 매체 조건의 3단계와 시작 전, 현재, 완료 상태를 구성했다.
- 진행 정보 전달 방식의 근거: 완료는 Check, 현재는 굵은 Olive Outline, 대기는 회색 번호와 점선으로 구분한다.
- 초안 검토 의견: 진행률처럼 보이면 사용자가 모든 답을 반드시 완료해야 한다는 압박을 받을 수 있었다.
- 추가 리서치와 출처: 능력단위평가 Progress 구성과 v2 기록 방식 찾기 와이어프레임
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: 성취율이 아니라 현재 위치를 보여주는 Pressure-free Progress로 확정했다.
- 웹디자인 적용 위치: 기록 방식 찾기의 목적, 시작 크기, 매체 조건 3단계

## 10. Components — Question Number

- 원본에서 파악한 역할·상태: 질문 순서와 현재·완료·대기 상태를 번호로 구분한다.
- 초안 기획 의도: 기록 방식 추천 질문의 현재 위치를 사용자가 예측하게 한다.
- 크기·선택·정답·오답 상태 수정 내용: 01 목적, 02 시작 크기, 03 매체 조건의 현재·완료·대기 상태와 연결선 Anatomy를 정의했다. 정답·오답은 사용하지 않았다.
- 이동·응답·채점 상태의 구분 근거: 기록 방식에는 정답이 없으므로 현재, 대기, 완료와 답 수정·건너뛰기·직접 탐색 행동만 구분했다.
- 초안 검토 의견: 추천이 선택 완료나 정답처럼 보이지 않도록 추천은 수정 가능한 초안이라는 설명이 필요했다.
- 추가 리서치와 출처: 능력단위평가 Question Number 구성과 v2 Recommendation Stepper
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Quiz 번호 체계를 기록 방식 추천의 Pressure-free Stepper로 재해석했다.
- 웹디자인 적용 위치: 기록 방식 찾기의 3단계 질문과 추천 결과의 답 수정 행동

## 11. Components — Quiz Option

- 원본에서 파악한 역할·상태: 사용자가 여러 답안 중 하나를 읽고 선택하며 결과 상태를 구분하는 요소다.
- 초안 기획 의도: 기록 목적과 방식 후보를 부담 없이 선택하게 한다.
- 선택·포커스·정답·오답·비활성 상태 수정 내용: Default, Hover, Focus, Selected, Recommended, Unavailable, Error 상태를 정의하고 정답·오답 대신 사용자 선택과 시스템 추천을 분리했다.
- 답안 선택 경험과 가독성 근거: 기록 방식에는 정답이 없으므로 선택 결과를 채점하지 않고 선택됨과 미선택만 명확히 구분한다.
- 초안 검토 의견: 추천이 정답처럼 보이면 브랜드의 기록 자율성과 충돌했다.
- 추가 리서치와 출처: 능력단위평가 Quiz Option 구성과 v2 기록 방식 질문 문항
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Recommended는 시스템 제안, Selected는 사용자의 직접 선택으로 의미와 아이콘을 다르게 했다.
- 웹디자인 적용 위치: 기록 목적, 시작 크기, 매체 조건의 선택 Option

## 12. Components — Timer

- 원본에서 파악한 역할·상태: 남은 시간을 기본·주의·위험 단계로 표시해 시간 기반 행동을 유도한다.
- 초안 기획 의도: 마감 시간을 재촉하지 않고 사용자가 기록에 필요한 예상 부담을 선택하게 한다.
- 기본·주의·위험 상태 수정 내용: 약 5분, 약 15분, 약 30분의 선택형 Duration과 READY, IN PROGRESS, PAUSED 상태로 수정했다.
- 시간 압박과 경고 강도의 표현 근거: 시간이 지나도 실패가 되지 않으며 “지금 한 줄”, “나중에 이어도 됨”을 함께 표시한다.
- 초안 검토 의견: Countdown과 위험 상태는 기록을 재촉하지 않는 DAMORI의 Pressure-free 원칙과 맞지 않았다.
- 추가 리서치와 출처: 능력단위평가 Timer 구성과 v2의 가장 작은 시작·부담 없는 복귀 원칙
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: Timer를 예상 시간 안내와 현재 기록 상태를 확인하는 Duration & Status로 재해석했다.
- 웹디자인 적용 위치: 한 줄 기록의 약 5분 안내, LOCAL 상태, 나중에 이어도 된다는 설명

## 13. Components — Card

- 원본에서 파악한 역할·종류: 관련 정보와 행동을 기본·통계·해설·결과 단위로 그룹화한다.
- 초안 기획 의도: 기록 방식, 추천, 시작, 복귀와 상태 정보를 목적별 카드로 구분한다.
- 기본·통계·해설·결과 카드 수정 내용: Method Card, Recommendation Card, Record Start Card, Recovery Card, Status Card와 Editorial Composition으로 수정했다.
- 콘텐츠 위계와 그룹화 근거: 대표 카드와 보조 카드를 같은 크기로 반복하지 않고 이미지, 제목, 상태, CTA 순으로 읽히게 한다.
- 초안 검토 의견: 동일한 형태와 크기의 카드가 계속 반복되어 화면이 단조로웠다.
- 추가 리서치와 출처: 숲소리의 대표·보조 카드 리듬, 상상마당의 Poster Grid
- 최종 결정: 변경
- 최종 변경 또는 유지 이유: 기능 Card와 브랜드 Editorial 영역을 분리하고 공통 색상·간격 Token으로 연결했다.
- 웹디자인 적용 위치: 방식 비교, 추천 결과, 한 줄 기록, 다시 이어가기, 제공 범위
